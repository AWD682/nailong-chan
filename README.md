# 奶龙酱

基于 NoneBot 的 QQ 机器人，支持聊天、群内主动接话、图片理解、语音回复和 H5 小游戏。

## 项目结构

- `bot.py` 是程序入口，根目录的 Python 模块实现聊天及游戏逻辑。
- `web/` 保存 H5 页面；`assets/` 和 `audio/` 保存运行时资源。
- `tests/` 保存离线测试；`deploy/` 保存 Linux 部署脚本。
- `requirements.txt` 列出 Python 依赖。

本机的 `.env`、聊天记录 `data/`、虚拟环境和临时文件不会提交到仓库。首次运行可将 `.env.example` 复制为 `.env`，填入自己的 QQ 机器人和 AI 服务配置。在项目根目录安装 `requirements.txt` 后运行 `python bot.py`；离线测试命令见文末。

## 功能说明

现有聊天插件处理私聊、群 @ 和回复机器人的消息。`active_chat.py` 处理群内未 @ 的普通文字消息：同一人连续发言会等待约 1.5 秒、合并最多 5 条，再由模型选择接话或沉默。每个群的主动回复至少间隔 5 秒，10 分钟最多 120 次；机器人消息和重复事件会被忽略。模型现在更愿意参与日常闲聊、吐槽和接梗。间隔是最短冷却时间，模型判断不适合插话时仍会保持沉默。

`chat_history.py` 将 QQ 实际推送给机器人的群文字消息保存在本机 `data/chat_history.sqlite3`，只供同一个群回看；每次写入或查询时清理超过 24 小时的消息。群友可用“@奶龙酱 整理聊天记录”“@奶龙酱 总结今天的群聊”等指令请求整理，也可以问“@奶龙酱 刚才群里谁说了作业？”等近期对话问题。整理最多使用时间范围内最新的 120 条消息，回答会提示是否只整理了部分内容。图片和附件不会保存，启用前的 QQ 聊天记录也无法补录；只有 QQ 已开放并实际推送的群消息可用。群成员应知悉机器人会暂存一天的群文字消息。模型内容检查失败时，会清空近期对话上下文，但不会立即删除这份按 24 小时保存的记录。

聊天记录整理会用奶龙酱自己的群聊语气讲述，不套用会议纪要标题；仍需忠于实际记录，有结论或待办才提，没有的内容不会编造。

## 新三国梗库

`new_three_kingdoms.json` 收录了 63 条《新三国》梗，`meme_refs.json` 保留“吃什么？是啊，吃什么”并新增 5 条日常口头禅，共 69 张。每张卡记录原句、关键词和适用语境；程序会按关键词、台词半句及同音字读音检索，最多给模型 12 张候选，由模型判断是否适合接梗。五句口头禅“吓哭了”“懂你意思”“没绷住”“!?强强?!”“是人啊？”也会提供给普通聊天和主动接话模型，遇到合适语境可主动穿插，每条回复最多一句，认真求助时不强行插梗。修改 JSON 后重启机器人生效。此功能依赖 `pypinyin`，云端更新时需重新安装 `requirements.txt`。

极短的接话口令可以在梗卡里填写 `call` 和 `completion`。当前发送“龙？”或“@奶龙酱 龙？”会直接接“可是帝王之征啊喵！”，而“屠龙”“龙是什么动物”仍按普通问题处理。

讨论虚构剧情时若说到“生死不明”，会接“生死不明？那就是死了”这句梗，并马上说明只是玩梗、剧情尚未证实；现实中的失踪、伤亡等情况不会这样接。

## 看图片

群里 @ 奶龙酱并附图、回复一张图让她看，或发图时在文字里叫“奶龙酱”，她会根据图片回答。私聊中直接发送图片也可以，只有图片没有文字时会默认请她描述图片。支持同一条消息或所引用消息中的图片，优先看当前消息附的图；一次最多处理前三张。图片会临时下载、传给当前配置的视觉模型，不写入 `data/`、聊天记录或对话缓存；缓存只保留“附带图片”的文字标记。下载失败、文件过大或格式不支持时，会请群友重发。需要当前模型具备视觉能力；现用的 `qwen3.8-omni-flash` 支持图片输入。

GIF 动图会在内存中抽取最多 8 帧，按播放顺序交给模型，让她结合前后画面判断动作。抽帧无法保证捕捉快速或细微变化；若 QQ 推送的实际文件只有静态封面，机器人也无法还原动图。日志中的“各图原始帧数”可帮助判断 QQ 是否送来了完整 GIF。此功能需要 Pillow；Windows 本地虚拟环境已安装，更新其他环境时先运行对应虚拟环境的 `python -m pip install -r requirements.txt`。

引用群友图片时，QQ 往往把原图放在事件的 `msg_elements` 里；程序会在 `reply` 没有图片时继续检查这些引用元素。如果 QQ 本次没有推送原图，机器人会明确请群友把图片和 @ 放在同一条消息中。更新云端安装包后须重启进程；若仍只收到“引用没有把原图传给我”，可在运行日志中查找“引用图片请求未取得附件”判断 QQ 是否推送了引用附件。

普通聊天的会话上下文现在最多保留 10 轮，群内主动接话可参考最近 20 条对话。云服务器更新时，将新版文件解压到现有项目目录，保留云端 `.env` 和 `data/`，运行 `.venv/bin/python -m pip install -r requirements.txt`，然后运行 `sudo systemctl restart nailong.service`。打包文件不包含这两项；上传后会从当时新收到的群消息开始积累记录。

群里 @ 奶龙酱时，`nailong_ai.py` 会让模型在生成文字的同时，从 `assets/memes/` 中挑选合适的表情包，先发送图片，再发送文字。模型未给出有效表情编号时使用 `wave.png`；图片发送失败时仍会继续发文字。私聊、仅引用回复和未 @ 的群消息不会走这套表情选择流程。新增表情包需先把图片放进目录，再在 `nailong_ai.py` 的 `STICKERS` 中登记文件名和适用场景。最近新增了两张登记：`craving`（馋蛋糕，用于聊到好吃的、眼巴巴想要时）和 `rofl`（原版奶龙捧腹爆笑，用于特别离谱好笑的发言）；`assets/memes/craving-cake.png` 是 `craving-cake-v2.png` 的近似旧稿，未登记，留作备用。

## 语音回复

群里 @ 奶龙酱或私聊时，明确说“发条语音”“用语音回复”“用嘴说出来”“念出来”，她会先生成短回复，再调用语音合成并发送 QQ 音频。说“唱两句”“唱首歌”时，会按主题生成一段约 10 秒的原创中文歌曲，要求单人声无伴奏清唱，不再循环单个“啦”音节或捧读歌词。明确指定现成歌名（如“用语音唱雨爱”）时，会说明当前不能按原词原调翻唱，避免把临时创作冒充原曲。音频生成模型有随机性，清唱效果需以实际试听为准。普通聊天不会自动发语音；问“你会唱歌吗？”只会正常回答。

已启用主动接话的群里，不 @ 她但明确要求语音时，她若决定接话也会发送音频；明确要求唱歌时会直接生成歌曲。未启用主动接话的群请用 @，因为 QQ 未必会把普通消息推送给机器人。

当前使用已有的 `AI_API_KEY` 和千问AI平台接口。普通语音默认使用 `qwen-audio-3.1-tts-flash`、`longpaopao_v3.1` 音色；可在 `.env` 里设置 `VOICE_MODEL`、`VOICE_VOICE`、`VOICE_API_URL`、`VOICE_API_KEY`。歌曲默认使用已实测可调用的 `qwen-audio-3.1-tts-next`，用提示词引导稚气女声、旋律和两句原创歌词；这个模型不能直接选用普通语音的音色 ID，生成的歌词、音色与时长也会有变化。若账号取得 Fun-Music 权限，可改用 `SONG_MODEL=fun-music-v1`（当前账号调用该模型返回 HTTP 403）；需要时还可配置 `SONG_API_URL` 和 `SONG_API_KEY`。语音及歌曲生成会消耗服务商额度。音频只在内存中暂存并上传给 QQ，不写进聊天记录；生成或上传失败时会提示。普通语音单次最多合成回复前 180 字、下载最多 8 MB 音频。Windows 修改后重启 `bot.py`；云端需上传新部署包并重启服务。

## 群聊小游戏

在群里发送 **@奶龙酱 游戏**（或“小游戏”）会打开带按钮的菜单，选择“喵话真假”进入按钮版答题，或点「奶龙快跑」「你画我猜」「喵话真假 H5」跳转到网页版。喵话真假先让玩家挑分类：8 个分类（游戏、动漫、数理化、影视、生物、计算机、歌曲、小说）可**多选 1-3 个**（再点一次取消，超出 3 个会被拒绝），选好点“开始答题”后连答 10 题收官结算，10 道题从选中的分类里混合抽出。

**实时出题**：在 `.env` 里配置 `QUIZ_API_BASE_URL` 和 `QUIZ_API_KEY`（当前接的是 DeepSeek 的 OpenAI 兼容接口，可选 `QUIZ_MODEL`，默认 `deepseek-chat`）后，每题优先调用该接口按选中分类实时生成偏难题目，并避开最近 40 题已出过的内容；接口未配置、超时或返回无效／重复题时，从选中分类的备用题库（`quiz_bank.py`，每类 12 题）抽题补足，游戏仍可进行。开启实时出题后每道题要多等几秒生成。AI 生成的知识题可能有事实错误，答案和解释需要按普通 AI 内容看待。API 密钥只写在 `.env`（已被 `.gitignore` 忽略），不要提交到代码里。每局只允许点开游戏的群友作答，重复点击不会重复结算；分类按钮卡本身不能更新状态，选中的进度用文字消息反馈；第 10 题答完直接公布总成绩。每张菜单、分类卡、题目和结果卡片 5 分钟后过期，重启机器人会清空未完成的局。普通聊天 @ 不会打开游戏菜单。

游戏菜单现在**始终附带网页链接**：已在云端 `.env` 配置 `H5_PUBLIC_URL` 时，菜单文字里带可点击的网页链接，并有「奶龙快跑」「你画我猜」「喵话真假 H5」跳转按钮（每行 2 个），群友在群里点“游戏”后既可以用按钮直接对话游玩，也可以进网页游玩；链接被 QQ 拒绝时会自动退回纯按钮菜单。未配置公网地址时（如本机开发），菜单会给出 `http://127.0.0.1:8765/run/`、`/draw/` 和 `/quiz/`——电脑上的 QQ 能直接打开，手机需要管理员配置 `H5_PUBLIC_URL` 后才能访问。

群消息的内嵌键盘附在机器人消息上，QQ 客户端决定实际显示位置，不能保证固定在输入栏上方。按钮使用回调事件；当前 `.env` 的 `QQ_BOTS` 已设置 `intent.interaction=true`。若换一份配置部署，也要开启该事件订阅并重启 `bot.py`。若 QQ 客户端或机器人权限暂不支持键盘，程序会提示菜单打开失败。

### 喵话真假 H5 试玩版

`bot.py` 现在同时在 `127.0.0.1:8765` 提供 H5 游戏。Windows 重启机器人后，用本机浏览器打开 `http://127.0.0.1:8765/quiz/` 即可试玩；也可以先停掉机器人，运行 `.\.venv\Scripts\python.exe h5_quiz.py` 单独预览网页。手机 QQ 不能打开电脑的 `127.0.0.1`。网页开局先点选 1-3 个分类（可点已选分类取消），每局抽 10 道判断题：`.env` 里配置了 `QUIZ_API_BASE_URL` / `QUIZ_API_KEY` 时优先由 DeepSeek 实时生成，不够 10 题或接口异常时从 `quiz_bank.py` 备用题库补齐，所以开局可能要等几秒。答题、判分和解释由服务端处理；同一道题重复提交不会重复得分。分类列表由 `/quiz/api/categories` 提供，答题中途的题目上会显示当前分类组合。游戏状态保存在内存中，30 分钟后或重启时失效；最近 40 题会被记住，避免连续开局撞题。现阶段 H5 成绩显示在网页里，可点“复制成绩”手动发回群里（成绩文案会带上分类名）；群内榜单留待下一轮完善。

云服务器上，网页服务默认只监听本机。将 HTTPS 域名反向代理到 `127.0.0.1:8765`，在云端 `.env` 设置 `H5_PUBLIC_URL=https://你的游戏域名`，重启 `nailong.service`，群内 `@奶龙酱 游戏` 菜单才会多出「你画我猜」「喵话真假 H5」跳转按钮。未配置公开地址时，聊天按钮版喵话真假照常可用。QQ 开放平台还需要将发送的域名加入消息 URL 配置；如果带网页链接的菜单被 QQ 拒绝，程序会尝试发送原有按钮菜单。可选设置 `H5_HOST` 和 `H5_PORT` 改网页监听地址和端口；公网部署建议保持 `H5_HOST=127.0.0.1`，由 HTTPS 反向代理对外提供服务。云服务器关机时网页游戏也无法访问。

### 你画我猜 H5 试玩版

浏览器打开 `http://127.0.0.1:8765/draw/`（云端为 `H5_PUBLIC_URL` + `/draw/`）即可玩：点「奶龙出个题」抽一个简笔画题目（动物/食物/物品/角色/动作共 48 个词，本地词库即时返回），也可以在输入框里自己写一个词（回车或点「就画这个」，最长 20 字），或者自由发挥；画板提供 10 色画笔、3 档粗细、橡皮、撤销和清空，支持鼠标和触屏。画完点「让奶龙酱猜」，整幅画缩到 640 宽后提交，AI **盲猜**（模型只看画，看不到题目）给出最可能的答案、最多 2 个备选和奶龙式点评；抽了题目时再由第二步单独判定是否猜中（意思对、特征对就算中），奶龙酱头像和页面结果随之变化。判定和答案都在服务端完成，页面刷新即清空作画。

看图用现有 AI 接口：默认直接用聊天模型（当前 `qwen3.8-omni-flash` 自带看图能力）；账号有独立视觉模型权限时，可在 `.env` 配 `DRAW_VISION_MODEL=qwen-vl-max` 优先使用（当前 API 中转没有该模型，保持默认即可），也可用 `DRAW_API_KEY`、`DRAW_API_URL` 单独覆盖接口。模型没配置或看图失败时页面会提示重试，画作不会丢失。上传体积上限 8 MB，超大会被拒绝。

### 奶龙快跑 H5（3D 跑酷）

跑酷主角的主体使用带纹理的独立 3D 模型 `web/run/nailong.glb`。`assets/run-model/reference/` 保存由现有立绘制作的正面、侧面、背面建模参考图；当前模型由正面图经腾讯混元 3D 2.1 生成，原始导出保存在 `assets/run-model/nailong-textured.glb`。浏览器通过本地 Three.js 和 GLTFLoader 加载模型，不依赖外网 CDN。开跑时角色会转身面向跑道，换道时短暂转向。模型没有骨骼动画，跑步动作通过局部形变让手脚交替摆动，背面另加袖口动作以免长发挡住手臂；旧程序化角色仅在模型加载失败时作为回退。若后续要更自然的关节动作，仍需给模型绑骨骼并制作跑步动画。

浏览器打开 `http://127.0.0.1:8765/run/`（云端为 `H5_PUBLIC_URL` + `/run/`）即可玩：熊大快跑/神庙逃亡式三车道 3D 跑酷。游戏逻辑全部在浏览器本地运行，服务端只提供静态文件。奶龙酱偷吃蛋糕被追着跑：左右换道、跳跃（跳矮栏）、滑铲（钻横杆）、原版奶龙立牌必须换道，路上捞 🐟 点心加分，速度会越跑越快。**奶龙酱有 3 颗爱心**：撞到障碍扣 1 颗、障碍被撞碎并获得 1 秒无敌（角色闪烁）；生命未满时，安全跑道偶尔会出现粉色爱心，捡到恢复 1 颗，最多恢复到 3 颗。3 颗扣完才摔倒结算，结算页展示奶龙酱捧腹大笑图。电脑用方向键/WASD/空格，手机触屏滑动（轻点当跳）。三款立牌参考用户提供的交叉手臂、大笑、侧身照片制作成透明底素材，按高障碍出现顺序轮流展示；碰撞规则与原高木牌相同。成绩 = 跑距 × 1.4 + 每块点心 15 分，最佳成绩保存在浏览器 `localStorage`。需要浏览器支持 WebGL；页面刷新即重新开始，没有服务端存档。

游戏音效使用 `audio/` 中的四段本地 `.m4a`：跳跃播放“安迪”、受伤播放“嘎嘎滴辣虾”、拾取回血爱心播放“猴辣，干巴爹”、结算时播放“氦气大笑”。点“开跑”后浏览器会激活音频；新音效会停止正在播放的上一段，重开一局也会停止结算笑声。上传云服务器时须同时更新 `audio/` 和 `audio_clips.py`。

三个 H5 游戏已适配手机竖屏：喵话真假和你画我猜缩小了顶部角色区，让题目、画板更早出现在屏幕中；画板颜色、笔刷和出题按钮扩大了触控区域，输入框使用 16px 字号避免手机浏览器自动放大。奶龙快跑在窄屏上把生命、分数等信息排成两行，支持轻点跳跃、左右滑动换道、上滑跳跃和下滑铲地。手机访问需要使用可从公网访问的 `H5_PUBLIC_URL`，不能使用电脑本机的 `127.0.0.1` 地址。

## 启用测试群

1. 请群主在**手机 QQ** 打开目标群的设置 → 机器人设置，选中奶龙酱，将“机器人可获取的群聊消息范围”改为“获取群内全部消息”，并开启“机器人主动在群聊内发言”。每个测试群都要单独设置。当前适配器能识别 `GROUP_MESSAGE_CREATE`，但只有 QQ 实际推送该事件，主动接话才会运行。
2. 在测试群里 @ 一次机器人，在运行日志中找到 `@[Group:xxxxxxxx]`，其中 `xxxxxxxx` 就是要填的 `group_openid`。
3. 在已有 `.env` 中新增一行 `ACTIVE_GROUP_OPENIDS=xxxxxxxx`。多个测试群用英文逗号分隔。没有填写时，主动接话保持关闭。
4. 重新运行 `.\.venv\Scripts\python.exe bot.py`。群里发送未 @ 的普通文字时，终端应出现 `GROUP_MESSAGE_CREATE`；若模型决定接话，还会出现 `主动接话已发送到群 ...`。

可用普通寒暄测试沉默，再用“今天作业好多，我有点难过”测试接话。模型会结合近期群聊自行判断，因此每次决定不一定相同。如果日志仍只有 `GROUP_AT_MESSAGE_CREATE` 而没有 `GROUP_MESSAGE_CREATE`，先检查上述群内消息范围设置；改代码或白名单无法补出 QQ 未推送的消息。当前 `QQ_BOTS` 的 `c2c_group_at_messages` 已开启，无需将它改成频道消息的 `guild_messages`。

若日志在每次 `Bot ... connected` 约 30 秒后反复出现 `websocket ... Trying to reconnect` 和 `TimeoutError`，这是 QQ 适配器固定的 30 秒 WebSocket 接收超时。项目通过 `qq_adapter.py` 将接收等待设为 120 秒。修改后须停止旧进程并重新启动 `bot.py` 才会生效；空闲超过 120 秒仍可能重连。这个设置只影响连接等待，不会改变 QQ 平台推送的事件类型。

当前使用的 `qwen3.8-omni-flash` 默认开启高强度思考，猜字等问题可能使回复超过 25 秒。程序对这个模型默认设置 `reasoning_effort="none"`，适合即时聊天；如需自行调整，可在 `.env` 设置 `AI_REASONING_EFFORT=low` 等模型支持的值。

若模型返回 HTTP 400、`data_inspection_failed`，表示这次提交的输入（可能包括近期对话和提示词）未通过服务商的内容检查，不是超时或余额用尽。直接聊天时程序会用一条含蓄双关接话，并清空该会话的近期上下文，避免连续失败；普通群主动接话遇到相同错误时会跳过本次回复并清空该群上下文。

离线验证：`.\.venv\Scripts\python.exe -m unittest discover -s tests -v`。
